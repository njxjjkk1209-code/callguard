### 三套数据通道（核心设计）
| 通道 | 路径 | 方向 |
|---|---|---|
| App ↔ Extension | App Group：blocklist.txt / identify.txt | App 写，Ext 读 |
| App ↔ Tweak | `/var/mobile/Library/CallGuard/tweak_rules.plist` | App 写，Tweak 读 |
| Tweak → App | `/var/mobile/Library/CallGuard/tweak_log.jsonl` | Tweak 写，App 导入后清空 |

Tweak 不能走 App Group：SpringBoard 拿不到 group 容器，只能固定路径。App 需 `platform-application` entitlement（已加）。

### 技术要点
- Hook 点：`SBDashBoardIncomingCallViewController -initWithCall:` 为主，`SBIncomingCallAlertItem` 为备
- 挂断三级降级：`TUCallCenter -disconnectCall:withReason:` → `TUCall -disconnectWithReason:` → `-disconnect`
- **关键坑**：私有 API 参数类型不确定（NSInteger/int/BOOL 混用），`performSelector` 传 NSNumber 会错位崩溃。必须用 `NSInvocation` + `methodSignatureForSelector` 按 `getArgumentTypeAtIndex` 真实类型塞值
- 同一来电 init 和 viewWillAppear 各触发一次，用 `callUUID` 去重（NSMutableSet + NSLock，上限 64）
- 配置热更新：每次来电 `stat` 检查 mtime，变了才重载
- 响铃无法归零，实测预期 0.1-0.3 秒后挂断

### 踩坑
- 批量替换 `try exportBlocklist()` → `syncExports()` 时把 syncExports 内部也替换了，造成无限递归，已修
- Logos 指令计数被注释里的 `%hook` 干扰，实际 2 hook / 2 end / 1 ctor 正常

## CI 云端编译打通（下午）

### 排队的真实原因
`macos-13` 已于 2025-12 被 GitHub 退役，标签仍在但**无容量**，表现为永远 queued、runner 未分配（白等 2.5 小时）。换成 `macos-15` 后 45 秒分配。

### 三个真实编译错误（全部修复）
1. `RuleStore.swift:98 'addRule' has been renamed to 'add(_:)'`
   → ObjC 方法 `- (void)addRule:(CGRule *)rule` 里的 "Rule" 与参数类型 `CGRule` 的名词部分相同，
   Swift 的 ObjC 导入规则（SE-0005）把它推断成 `add(_:)`。
   修法：头文件里显式 `NS_SWIFT_NAME(addRule(_:))`，并给同组方法全部加上固定名。
2. `SettingsView.swift invalid redeclaration of 'body'`
   → `GuideSection` 里 `let body: String` 与 `var body: some View` 同名。改属性为 `text`。
3. `Tweak.xm:376 receiver type ... is a forward declaration`
   → Logos 对未声明类只生成 `@class`。`[self valueForKey:]` 无法解析。
   修法：`id selfObj = (id)self;` 再发消息，不改 Logos 的声明行为。

### Theos 打包的坑（关键）
- `make package` **硬性要求** `$THEOS/bin/dm.pl`，报 `requires dm.pl`，**不回落 dpkg-deb**。
- macOS 自带 perl 缺 dm.pl 依赖的压缩模块，且 `perl dm.pl --help` 返回非 0（不代表不可用，是它不支持 --help）。
- 最终方案：**只 `make clean all` 编译，自己用 `dpkg-deb --build --root-owner-group` 打包**。
  rootless 结构：`/var/jb/Library/MobileSubstrate/DynamicLibraries/{dylib,plist}`。
- 另需 `brew install ldid`：Theos 的 ldid 是 submodule，`--depth 1` 克隆常缺失，
  表现为 `ldid: command not found`（编译已过，只卡签名）。

### CI 调试手段（重要经验）
GitHub Actions 的 **job logs 端点需要 admin 权限**（public repo 也一样，403），artifact 下载需要登录。
可行通道：
- **check-runs annotations 免 auth 可读** → 把日志逐行 `::error title=xxx::内容` 输出即可远程看到。
- **把日志 push 回 `ci-logs` 分支**，再用 contents API（base64）读取，最完整。
  workflow 需 `permissions: contents: write`，commit 带 `[skip ci]` 防止循环。
